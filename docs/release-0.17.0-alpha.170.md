# 0.17.0-alpha.170 — ordered input admission and grid-pair evidence

Audit and commissioning record: [issue 291](https://github.com/fuchs-1978/ioBroker.ems-optimizer/issues/291). Based on main 32f4e4ec0e161a1b246b3cdad1266d298caae300 (alpha.169). SMA PR919 and js-controller issue3574 describe publication delays; they do not prove that reversed states arrived at this EMS.

## Audit and implementation

main.js previously admitted foreign stateChange events without source-time ordering. Preload and wallbox initialization read before subscribing and could overwrite a newer event with a delayed read response. Existing own-state echo and object-creation reference guards were already present. A shared InputStateCache now admits events and reads, with subscriptions established before reads. Per-ID revision evidence rejects a read superseded by any event since that read began, including equal-ts updates and deletion. An older valid numeric ts cannot pass the retained source watermark. Rejected events do not reach heater write proofs, listeners or production capture. Direct diagnostic probes and SQL adapter-process metadata reads never populate the measurement cache and remain separate.

Equal-ts events may legitimately change value, ACK or quality and are accepted in arrival order; no unavailable sequence number is invented. Unchanged values with newer ts remain eligible. Missing/invalid/nonpositive or more-than-one-second future timestamps do not advance the valid watermark and are never rewritten to arrival time. Their original fields remain available; grid/measurement validation rejects invalid evidence. The grid reader and core measurement freshness require numeric timestamps. A valid later sample can recover after an invalid/far-future one without waiting for that bad timestamp. Deletion retains the watermark and read revision. Own ACK=false user commands keep their separate command semantics because locally generated own publication timestamps are monotonic and may be ahead of wall-clock milliseconds. lc is not a freshness or ordering substitute. A source clock reset below its accepted watermark needs clock recovery or a reviewed EMS restart; this release deliberately does not infer resets from old values.

## Grid source time contracts

Observer balances/recommendations, realtime control, EHZ direct feedback, wallbox output/admission/telemetry hold and electrical queued-output validation use the shared GridMeasurement reader. Existing groupNet accounting still independently enforces its stricter original-time inventory and skew/age constraints. The original per-source 30-second grid age limit and independent phase/device/operator/release protections are not extended.

Admin's new **Grid timestamp contract** defaults to **Publication times (maximum 5 s skew)**. This reuses the existing 5-second wallbox probe tolerance across the other grid paths, reports the actual skew and accepts only individually fresh, acknowledged, good-quality, nonnegative numeric source values. Publication timestamps represent writes rather than necessarily physical observations; bounded skew does not prove a common telegram. Both source ts values are reported.

Select **Shared telegram receipt time (exact match)** only for a source that guarantees both values carry the same telegram receipt ts, such as the SMA test adapter in PR919. A split telegram update cannot then receive fresh export credit from mixed timestamps. Do not infer that contract from an adapter name/version or select it for an unverified publication-time source. No current installation setting is changed by this work. A source publishing unchanged zeros only on change must provide its own genuine bounded heartbeat; rereading an old zero cannot manufacture freshness.

When individually valid values temporarily disagree beyond the selected skew, a previously observed suitable pair may support conservative continuation only within its ORIGINAL 30-second age: zero export credit and import at least the previous/current imported value. It is explicitly marked held, with original and pending timestamps. No new nonzero actuator command may use held pair evidence. A witnessed owned charger can keep its exact current under all existing independently fresh protection checks and high-water reservations. Starts wait, unprovable continuation stops, and zero safety commands remain allowed. Missing/bad-quality/unacknowledged/old sources never receive this exception. No duration extends on repeated reads of unchanged timestamps.

Diagnostics.Snapshot_JSON.inputStates contains the bounded rejection counter and last rejection; gridMeasurement exposes time contract, skew, original timestamps and held state. Rejection logs are debug-only with one global message per minute. No new raw logging, SQL/history query or background plant monitor is added.

## Verification and installation

Targeted tests exercise reversed events, delayed same-ts preload/output initialization, equal-ts value/ACK/quality changes, unchanged values with new ts, deletion, invalid/future timestamp recovery, original-age expiry, publication/shared-receipt contracts, a 3.2-second split update and recovery, no-write established charging, and independent overload shutdown. Existing bare-VM test harnesses inject the same new pure reader as the production loader. Original age-boundary tests use a coherent pair to distinguish freshness from the newly added skew rule. The standing-phase heater test now simulates a genuinely unrefreshed source rather than attempting to overwrite newer telemetry with an old event. Historical comparison retains production decisions and compares the prior grid decision fields separately from newly tested metadata.

Final test counts, packed-install and Node22/24/26 CI results are recorded in issue291/PR. These are offline software tests, not proof of installation or complete real protection/plant acceptance.

After merge, install from ioBroker Admin's GitHub/custom URL using https://github.com/fuchs-1978/ioBroker.ems-optimizer (or the exact merged revision recorded in issue291). Check System.Version=0.17.0-alpha.170 and normal startup. For the receipt-timestamp SMA test source, deliberately select the matching shared-receipt option in EMS Admin after checking that source contract; the compatible publication-time default does not promise exact telegram pairing. No automatic installation or SMA/controller modification is performed. A GitHub Release/npm publication is separate.

## Remaining limits

This cannot reconstruct superseded/missing intermediate samples, remove controller/transport delays, prove source clocks correct, or distinguish reordered equal-ts events without a source sequence. Bounded publication skew is not atomicity. The last pair is not made fresh by rereading it. Different source clocks must be aligned or declared appropriately. Safety remains conditional on the independently observed source/protection contracts, not on successful database writes alone.
