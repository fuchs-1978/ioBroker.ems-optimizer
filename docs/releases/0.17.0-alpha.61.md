# 0.17.0-alpha.61 – bounded display persistence and less JSON churn

## Changes
- Acknowledged derived Forecast/Plan/Chart JSON display states retain at most one in-flight value and one newest replacement per ID during slow persistence. All callers share the drain promise; adapter completion handlers are attached once per drain.
- Control/validity flags, configurations, device reservations, actuator commands and DecisionRecords remain on their existing ordered paths. Diagnostic capture sees every update before display persistence is coalesced.
- Debug history serialization reuses unchanged event/trace exports. New events, enriched stop reasons, trace samples, reset and restored rings invalidate the affected export.

## Validation and limits
Regression coverage stalls a write while sending 10,001 replacements, checks bounded retention/latest delivery, failure recovery, FIFO safety/record writes, cache/flush completion and enriched event/trace/reset preservation. Run the complete Node-20 CI and package checks before publication.

No change to control policy, source freshness, timers, SQL retention, source recording, or productive installation. This removes a code-level unbounded queue for eligible display series and repeated serialization; it does not prove that the previous OOM was caused by EMS, prescribe a specific MB saving, or prove a successful real 24-hour SQL replay. Measure RSS, heap and uptime under comparable load after manual installation. Ordered non-display writes remain a separate follow-up if persistence stalls.
