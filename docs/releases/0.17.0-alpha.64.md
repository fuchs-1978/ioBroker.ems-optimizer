# 0.17.0-alpha.64

Behebt zwei reproduzierte Recorder-Verstärkungen: Ein Ereignisfenster erzeugte bisher pro Quellenpoll einen vollständigen Produktivdatensatz; ein voller gültiger Vorpuffer erzeugte mit 16-Proben-Gruppen mehr Datensätze als die Warteschlange aufnehmen konnte. Rein numerisch wechselnde Stoppgrundtexte konnten das dichte Fenster ständig verlängern.

- Dichte analoge Rohupdates werden vor dem Bau vollständiger Cache-Frames in `recording.sources` gebündelt: ungefähr 1 s, maximal 128 Proben bzw. Zielgröße 32 KiB Rohproben. Originale Quellen-/Empfangszeit, `lc`, ACK/q, NULL und Sample-Sequenz bleiben erhalten. Einzelne größere Proben können über der Zielgröße liegen.
- Befehle, wichtige Quellen-/Qualitätswechsel, Ausgangszustände, Bestätigungen, Schutz- und Timergrenzen bleiben unmittelbar. Originale Stoppgründe werden unverändert gespeichert; nur ihr numerischer Text wird für den Ereignisvergleich normalisiert.
- Der begrenzte Vorpuffer wird in größeren Rohgruppen geschrieben, bereits abgegebene Gruppen bei überlappenden Fenstern nicht erneut kopiert. Unversendete dichte Proben beim Beenden werden als diagnostischer Pufferverlust gezählt; ein Shutdown garantiert keine restliche Persistierung.

Die Warteschlange wird nicht vergrößert; anhaltende Speicherfehler können weiterhin explizite Verluste verursachen. Die Änderung betrifft die Diagnose, nicht Regelung, Schutzgrenzen oder SQL-Konfiguration. Ein bestandener synthetischer Lasttest beweist keine reale RAM-Ersparnis, keinen behobenen Connector-Timeout und keine vollständige 24-h-Abnahme. Installation bleibt manuell; keine Scorepunkte allein durch Veröffentlichung.

Regressionen prüfen Mehrquellen-Polling, vollen Vorpuffer bei verzögerter Speicherung, Rohzeit-/Qualitätserhalt, Ereignisreihenfolge, numerische Stopptexte, Fehler-/Checkpoint-Erholung und Restpuffergrenzen. Die vollständige Suite und Paketprüfung werden vor Veröffentlichung auf Node 20 ausgeführt.
