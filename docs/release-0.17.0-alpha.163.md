# 0.17.0-alpha.163 — repository quality and timer ownership

This release implements operator-selected checker points 1, 3, 4, 5 and 6. Point 7 (npm publication and ioBroker Latest admission) remains excluded. Maintainer contact details, repository topics and optional tooling are separate remaining tasks.

- Standard `.github/workflows/test-and-release.yml` uses the official ioBroker check and adapter actions. Node.js 22, 24 and 26 run the existing unit suite, package checks, isolated controller integration, packed installation and historical equivalence comparisons. This workflow validates tags but does not publish. The separate manual GitHub prerelease workflow uses `npm ci` and the same static checks.
- Ordinary engine, market-price and history request timers delegate to the adapter timer API. Existing engine shutdown gates and history cancellation remain active. Native timers are explicit exceptions for bounded recorder/SQL/shutdown deadlines that must settle after normal adapter timers have been cleared; changing these to automatically cancelled timers could leave shutdown promises unresolved or lose late-result evidence. Standalone offline tools retain native timers.
- Shared `@iobroker/eslint-config` checks runtime code, tools and tests. Existing source formatting is retained. VM engine files share only their actual declared bindings and injected API names; mapping placeholders have narrowly documented exceptions. Checks reject undefined names, duplicate object keys and bare runtime timeout calls. An identical overwritten diagnostic key and unused locals were removed without changing outputs.
- All 533 Admin grid fields are checked at xs/sm/md/lg/xl widths. Widths must be integers from 1 to 12, full width on phones and nonincreasing on larger displays. Table-column widths are not grid fields. The current layout already satisfied the full responsive checker: no visual layout rewrite was needed. Actual browser appearance remains a separate acceptance task.
- A committed lockfile fixes development and runtime dependency resolutions for `npm ci`. Shared lint dependencies are development-only; lockfile and lint configuration are excluded from the installed adapter package. Runtime dependency declarations remain unchanged.

## Scope and validation limits

No additional SQL queries, plant experiments, source logging or changed energy allocation rules are introduced. The isolated integration test forces `CI=true`; the Sentry plugin disables itself in this environment, and the test harness also sets diagnostic reporting to `none` before adapter startup. It never uses production configuration or actuator mappings.

The responsive audit and official package/schema checks are automated checks, not a physical plant or visual commissioning. A local run of the official repository checker is distinguished from a new remote bot report. Remaining checker findings are not silently accepted or closed. Version in main, published GitHub prerelease and actual installation are separate facts.

Local validation: clean `npm ci`, ESLint, all 533 responsive fields, metadata checks, 61 official package/schema tests, 3,294 unit tests, installed tarball (276 files / 747 states) and both historical comparisons passed. The official repository checker 5.23.2 JSON-config module traversed the complete current configuration with no errors or warnings. Its complete repository/network run was unavailable because the GitHub API proxy timed out; this is not a fresh remote bot report. The local controller startup was blocked by this cloud sandbox's `uv_interface_addresses` restriction; regular GitHub runners must supply the integration result.

The historical lifecycle comparison records bootstrap source text. It aligns only the new `engineTimers.setTimeout/clearTimeout` delegate spelling to its previous API spelling before hashing; executed bootstrap scheduling and timer ownership remain covered by separate tests. No actuator trace or diagnostic value is filtered for this change.
