# 0.17.0-alpha.301

The appliance deadline field accepts `06:00` (finish by the next 06:00) or `+4` (start within four hours of the remote-start release). Positive decimal hours up to 48 are supported. The release state change timestamp anchors the window across replanning, program changes and adapter restarts. A new physical release opens a new window. Program runtime may extend past the start deadline. Expired windows cannot issue a start; status reports `start window expired`. A valid complete forecast, usable measured/configured profile and the normal write permissions remain required.

`Plan.Appliances_48h_JSON` publishes a versioned 48-hour diagram payload, updated by the appliance scheduler. `devices` contains each currently planned, dispatched or running appliance with row ID, stable physical `deviceKey`, name, program, profile source/sample count, grid phase, start/end, optional start deadline and `series`. Each series contains 192 absolute quarter-hour timestamps with `valueW` (mean W) and `energy_kWh`. Off-grid starts and partial quarters are integrated by their overlap. The top-level `series` sums scheduled devices; observation-only plans are labeled `scheduled: false` and excluded. Actual running and dispatched loads are included in either mode. With global writes disabled, waiting automatic plans are previews too. `unresolvedDevices` identifies running loads whose profile is missing or exhausted; the predicted sum is incomplete for these loads. `valid` refers to the underlying current EMS plan; stale waiting plans disappear, while running profiles remain visible.

This is an additional display payload. Do not add it to an existing forecast that already includes these appliances. It does not change historical house-load correction or create a measured power-history series. Learned profile data remains under `Devices.ProgramProfiles.*`.
